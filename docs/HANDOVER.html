01

Em uma frase

Kobly (domínio koblay.io, package koblay) é o console SaaS de automação de recuperação de vendas: eventos de checkout disparam campanhas de e-mail/WhatsApp/SMS com fluxo visual, billing via Asaas, e suporte (IA + humano) multi-tenant no Supabase.

Multi-tenant

Isolamento por organization_id via RLS. Signup → confirma e-mail → onboarding RPC create_own_org (plano Starter).

Motor de automação

Checkout/postback → leads → passos de campanha. Workers process-steps / process-bulk (cron). Supressões, unsub assinado, dead-letter.

Project ref documentado: hvkuymprmfrjrgpqaxbw (supabase/config.toml, docs go-live). Staging separado: a confirmar (só um projeto aparece na doc).

04

Como rodar local + envs

npm install
cp .env.example .env   # preencher VITE_SUPABASE_URL + VITE_SUPABASE_ANON_KEY
npm run dev            # http://localhost:5173
npm run build          # → dist/
npm run preview
Variável / secretOndeUso
VITE_SUPABASE_URL.env / NetlifyClient Supabase (obrigatória no build prod)
VITE_SUPABASE_ANON_KEY.env / NetlifyAnon key pública no bundle
deepseek_api_keyVaultEdge ai-chat
resend_api_key, resend_from, resend_sending_domainVaultEnvio / remetente plataforma
Credenciais Z-API (instance/token)VaultWhatsApp — hoje global, não por org
asaas_api_key, asaas_env, asaas_webhook_tokenVaultBilling + auth do webhook
unsubscribe_secret, resend_webhook_secretVaultUnsub HMAC · verificação Svix (se ausente = fail-open no webhook)
Integrações leem o Vault via RPC get_secret() — não “Edge Functions → Secrets”. Docker Compose local: não há no repo. Edge deploys: supabase functions deploy <nome> --project-ref ….

Golden path

  1. Signup / login → org criada (ou persona DEV)
  2. Integrações: webhook/postback (checkout) + domínio/remetente Resend + (opcional) WhatsApp
  3. Campanhas: FlowBuilder (gatilho → tags → e-mail/WA/SMS) → ativar
  4. Evento real → lead → worker executa passos → métricas no Dashboard/Pipeline
  5. Planos: assinar via Asaas (PIX/assinatura); gates de limite no Postgres

Convenções para quem assume

  • Sem CONVENTIONS.md / AGENTS.md / CLAUDE.md na raiz — fonte de verdade: README.md + specs em docs/superpowers/.
  • Migrations: supabase/migrations/00NN_nome.sql. Próximo número livre após 0066 (não reusar 0064 cancelada sem ler o plano).
  • Edge: lógica pura em _shared/ + deno test; copiar/inlinar dentro da function no deploy (não importar ../_shared/).
  • Tokens UI: aliases semânticos (--surface-*, --text-*, --accent) — não hardcodar hex solto.
  • Gates de plano vivem no Postgres, não no JS (front escreve PostgREST).
  • verify_jwt versionado em supabase/config.toml — webhooks públicos autenticam por token próprio.
